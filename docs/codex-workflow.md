# Codex 建模工作流

Codex 调用建模工具时应保持以下顺序：

1. 调用 `get_status`，读取 Max 版本和能力清单。
2. 调用 `get_scene_summary`，获取当前场景序号、对象名和选择状态。
3. 对复杂修改先使用 `dry_run=true`，确认命名冲突、尺寸和能力限制。
4. 复杂修改先记录 `scene_seq`，写操作传入 `expected_scene_seq`，如果场景已变化就重新读取。
5. 每次只提交一个可回滚的修改事务。
6. 修改后调用 `verify_scene`，确认对象存在、变换正确、命名没有冲突。
7. 需要连续创建多个基础体时，优先在一次规划中批量安排工具调用，避免让当前选择成为隐式输入。
8. 需要视觉判断时，再请求视口截图；截图不是场景数据的替代品。

## 工具设计规则

- 参数使用世界单位和明确的角度单位。
- 返回稳定的节点引用、场景序号和变更摘要。
- 不依赖当前选择作为隐式输入。
- 不把 MAXScript 字符串拼接暴露给 Codex 作为主工作流。
- `create_mesh` 使用世界坐标顶点和 1-based 三角面，适合墙体、道路和自定义楼体轮廓。
- 所有错误都返回 `ok=false`、错误码和可执行的修复提示。
- 连接默认使用 `tcp://127.0.0.1:8765`；bundled HTTP bridge 使用独立的 `9766` 端口。
- 不假设 `getMAXVersion()`、原生 Python 或商业渲染器存在；版本信息从 `maxVersion()` 和能力清单读取。

## 版本适配

桥接启动后报告 `max_version` 和 `capabilities`。工具根据能力清单选择实现；当某个版本不支持某项操作时，返回结构化的 `unsupported_capability`，不要静默改变建模结果。
